# Crash 926 — 多人同時下注 Crash 網頁遊戲（模擬版）

**線上試玩：https://acc2023156.github.io/Crash/**

> 本專案使用**模擬遊戲幣**，不涉及真實金錢，僅供遊戲開發與演示。

## 功能

| 項目 | 說明 |
|---|---|
| 自適應手機 | 桌機：左側下注面板＋下注列表、右側曲線；手機（≤900px）：曲線 → 下注面板 → 列表，主按鈕固定在下方，單手可操作 |
| 多人同時下注 | 內建 **100 個暫代帳號**（`bot001`~`bot100`），每局隨機抽 **5~60 人**（可在「模擬設定」調整）於下注階段陸續下注並自動兌現 |
| 帳號策略 | 保守（1.05–1.6×）／穩健（1.5–3×）／冒險（2.5–10×）／衝月（8–100×），下注金額依餘額百分比；破產自動補回 1000 |
| 玩家操作 | 手動下注、自動兌現倍數、手動兌現、½ / 2× / Max、下注階段外會排入下一局；空白鍵快捷 |
| 自動投注 | 局數（0 = 無限）、贏／輸後加碼 %（0 = 回原始金額） |
| 公平性驗證 | 每局先公開 `SHA256(seed)`，崩盤後公開 seed，可在頁面重新計算驗證 |
| 紀錄 | 本局下注、100 帳號排行（餘額／損益）、我的紀錄；資料存在 localStorage |

## 遊戲規則與數學

- 回合：**下注 7 秒 → 倍數上升 → 崩盤停留 3.5 秒**
- 倍數曲線：`m(t) = e^(0.00006 · t_ms)`（約 10 秒 1.82×、20 秒 3.32×、30 秒 6.05×）
- 崩盤點：`r = SHA256(seed:crash926:局號)` 前 52 bits / 2^52，`crash = max(1, floor(99 / (1 − r)) / 100)`
  - 莊家優勢 1%，中位數約 1.98×，約 10% 機率 ≥ 10×
- 自動兌現倍數 ≤ 崩盤點即成功，派彩 = 下注 × 兌現倍數

## 架構規劃：從「單機模擬」到「真・多人連線」

目前 `engine.js` 在瀏覽器裡扮演「伺服器」；它刻意不依賴 DOM，事件介面（`round / bet / cashout / crash`）即為未來的網路協定。

### 第二階段：權威伺服器
```
瀏覽器 (ui.js) ──WebSocket──►  Node.js 遊戲伺服器 (engine.js 搬過去)
                                  ├─ Redis：回合狀態、pub/sub 廣播、線上人數
                                  └─ PostgreSQL：帳號、下注、回合紀錄、seed 鏈
```
1. **伺服器是唯一時鐘**：只廣播 `run` 的起始時間，客戶端依 `m(t)` 自行繪製；兌現以伺服器收到請求的時間判定，避免客戶端作弊。
2. **Seed 鏈**：預先產生 N 個 hash chain（`seed_i = SHA256(seed_{i+1})`），反向使用，玩家可驗證整條鏈未被竄改。
3. **訊息協定**（JSON）：`round {id, hash}`、`bet {user, amount}`、`run {startAt}`、`cashout {user, m}`、`crash {m, seed}`；客戶端送 `bet / cancel / cashout`。
4. **下注節流**：同一局每帳號一注、下注階段外拒絕、金額上下限、速率限制。
5. **機器人**：100 個暫代帳號改由伺服器端 worker 執行，與真人走同一條下注 API，方便壓力測試。
6. **擴充**：單一遊戲房由一個 process 負責時鐘；多台 WebSocket gateway 透過 Redis pub/sub 廣播，可支撐上千人同時在線。
7. **資料表草案**：`users(id, name, balance)`、`rounds(id, hash, seed, crash, started_at)`、`bets(id, round_id, user_id, amount, target, cashed_at, payout)`。

### 第三階段
登入（OAuth）、聊天室、排行榜、音效、PWA 安裝、管理後台（調整 bot 數量、查看回合統計）。
